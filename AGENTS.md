# Инструкции для работы над сайтом Техникума

## Проект и работа

- В начале задачи прочитай `docs/STATUS.md` и `docs/DECISIONS.md`. После существенного изменения обновляй состояние проекта, различая выполненное и непроверенное.

- Техникум — бистро. Никогда не называй его рестораном, в том числе в интерфейсе, текстах и общении. Используй «сеть бистро», «выбрать бистро». Это прямое правило пользователя, приоритетное относительно терминологии источников.

- Разрабатываем сайт Техникума на Next.js, App Router, TypeScript и Tailwind CSS. Используем npm.
- Стили компонентов пиши utility-классами Tailwind CSS. Не создавай CSS Modules и отдельные CSS-классы для компонентов. В `globals.css` оставляй импорт Tailwind, общую тему и необходимые глобальные подключения; дизайн-токены задавай через `@theme`.
- Делаем общий сайт сети. Структуру определяет пользователь; дерево из исходников не является поручением реализовать весь сайт. Принятые решения смотри в `docs/DECISIONS.md`.
- Общаемся по-русски. Работаем маленькими задачами, выполняем только текущий согласованный этап.
- Если пользователь просит подумать, исследовать или обсудить — не реализуй интерфейс без запроса.
- Не добавляй новые разделы, интеграции или зависимости ради возможных будущих задач.
- В конце кратко сообщай, что изменено, что проверено и что проверить не удалось.

## Источники и факты

- До задач о бренде и содержимом прочитай `docs/research/README.md`, затем нужный раздел первоисточника. Исходники находятся в `D:\tekhnikym\input`.
- Предлагаемый смысловой источник: введение в бренд 2.0 от 25.10.2026 (S7). Предлагаемый источник айдентики: фирменный стиль v09 от 14.10.2026 (S2). Эти приоритеты становятся рабочими после подтверждения пользователем.
- Для каждого существенного факта фиксируй источник и область применения; для меняющихся данных также статус и актуальность.
- Наличие записи в документе не подтверждает её актуальность, применимость ко всей сети или готовность к публикации.
- Не придумывай адреса, телефоны, часы, блюда, составы, цены, акции, награды, отзывы, даты, статистику и условия франшизы.
- Не переноси данные одной локации на все бистро сети. Не превращай планы, сезонные макеты и стратегические ориентиры в действующие предложения.
- При расхождении источников явно обозначь противоречие. Не объединяй версии и не выбирай коммерческие значения догадкой.
- Если сведений нет, пометь их как неизвестные в рабочей документации. Для разработки можно предложить явно обозначенный черновик или оставить блок без неподтверждённых данных.
- Новые тексты и дизайнерские идеи называй предложениями, пока они не приняты пользователем. Пересказ источника не выдавай за дословно утверждённый текст.
- Не публикуй внутренние документы, извлечения и коммерческие сведения вместе с публичными ресурсами сайта.

## Бренд и визуальные решения

- Ориентир бренда: интересная гастрономия на каждый день без барьеров, понятность и дружелюбие без снобизма.
- Пиши просто и на равных; юмор уместный, без насмешек над гостем. Обращение на «ты» не считай обязательным.
- Соблюдай оригиналы логотипа, разрешённые цвета, шрифты и охранные поля из S2. Не собирай логотип текстом и не генерируй замену готовой айдентике.
- Используй строго шрифты из `D:\tekhnikym\fonts`, скопированные в `src/fonts` и подключённые через `next/font/local`. Tehnikum Light — акцидентный набор (`font-brand`); Courier New Regular/Bold — текст (`font-brand-mono`). Не используй системные подмены, Google Fonts и искусственные начертания. Courier New Italic хранится в комплекте, но по текущему брендбуку не применяется без отдельного указания пользователя.
- Синий — только для фирменных иллюстраций. Крафт — оригинальная фактура, не выдуманный фирменный HEX.
- Не переноси размеры и сетки рабочих примеров брендбука в универсальные правила сайта.
- Если нужного оригинала нет, сообщи об этом; предложенную замену явно обозначь и не выдавай за фирменный материал.
- Референсы — материал для обсуждения. Не считай все детали референса утверждёнными.
- Прямой референс клиента — https://gorynich.com/: сторителлинг, ощущение презентации, карта выбора ресторанов. Учитывай эти ориентиры в порученном блоке, сохраняя айдентику Техникума. Точные разделы, взаимодействия и технологии не считай автоматически согласованными. Факты и коммерческие условия «Горыныча» не переносить.

## Проверки

- Выполняй проверки соразмерно изменению; для кода доступны `npm run lint`, `npm run typecheck`, `npm run build`.
- В PowerShell при запрете скриптов используй `npm.cmd`.
- Не заявляй об успешной установке, сборке или визуальной проверке, если они не выполнены.
